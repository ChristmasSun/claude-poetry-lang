# Making Lament Standalone

## Current State: Self-Hosting with Python Bootstrap

Lament is self-hosting (compiler written in Lament) but requires Python as the host runtime.

```
You type: python3 -m lament.cli run mycode.lament
          ↓
          Python interpreter loads
          ↓
          Lament interpreter (Python code) executes
          ↓
          Your Lament code runs
```

## Path to Standalone Binary

To make Lament fully standalone (no Python required):

### Option 1: Compile to Native Code
```
Lament source
    ↓ (Lament compiler generates)
C code or LLVM IR
    ↓ (C compiler or LLVM)
Native executable
```

**Steps:**
1. Modify bytecode generator to emit C code instead
2. Add C runtime library
3. Use gcc/clang to compile to binary
4. Result: `./lament mycode.lament` (no Python!)

### Option 2: Bundle with Python
```bash
# Use PyInstaller to bundle everything
pyinstaller --onefile lament/cli.py

# Result: single executable
./lament mycode.lament
```

**Pros:** Easy, works now  
**Cons:** Still has Python inside (bigger binary)

### Option 3: Write VM in C/Rust
```
Lament bytecode VM (written in C/Rust)
    ↓ executes
Lament bytecode (generated by Lament compiler)
```

**Steps:**
1. Rewrite `lament/bytecode.py` VM in C or Rust
2. Lament compiler still written in Lament
3. Compile C/Rust VM to binary
4. Result: `./lament-vm bytecode.lmnt`

## Why Self-Hosting Still Matters

Even with Python dependency:
- ✅ Compiler logic is in Lament (can be maintained in Lament)
- ✅ Can compile itself (proves language is complete)  
- ✅ Bytecode format is language-native
- ✅ Can bootstrap from just Python + Lament source

## Comparison to Other Languages

**Python:**
- Written in C
- Needs CPython to run
- Self-hosting: PyPy (Python in Python) but still needs C-Python to bootstrap

**JavaScript:**
- V8 engine in C++
- Needs engine to run
- Self-hosting: engines can compile themselves, but need C++ to start

**Java:**
- JVM in C++
- Needs JVM to run  
- Compiler (javac) in Java, but needs JVM

**Lament:**
- Interpreter in Python
- Needs Python to run
- Compiler in Lament ✓ (self-hosting achieved)

## Quick Answer

**Q: Why still use Python if it's self-hosting?**

A: Self-hosting means the *compiler* is written in Lament. But you need *something* to execute that compiler. Python is the bootstrap runtime.

**To use Lament without Python:**
1. Compile Lament VM to native code (C/Rust)
2. Or bundle Python with executable (PyInstaller)
3. Or compile Lament to native code directly

**But for now:**
```bash
python3 -m lament.cli run mycode.lament
```

This is normal! Even C compilers need a C compiler to compile themselves.
